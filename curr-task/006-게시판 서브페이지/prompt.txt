[ 공지사항 게시판 생성 프롬프트 ]
-첨부: 게시판 각 화면 이미지(4개)
-프롬프트:
첨부된 4개 화면(목록 / 상세 / 글쓰기 / 수정)과 동일한 UI로 "What If" 공지사항 게시판을 구현해줘.

[개발 방식]
- 현재 단계는 DB 없이 localStorage 기반으로 개발한다.
- 개발 완료 후 Firebase(Firestore + Storage)로 마이그레이션할 예정이므로,
  반드시 `localstorage_to_firebase_guidelines.md` 지침을 먼저 읽고 그대로 따른다.
  (지침과 이 프롬프트가 충돌하면 지침을 우선한다.)
- UI 코드에서 localStorage를 직접 호출하지 말고, 데이터 접근 계층(Repository/Service)을 분리한다.
  마이그레이션 시 이 계층만 Firebase 구현체로 교체하면 되도록 한다.
  (비동기 async/await 인터페이스 사용, Firestore 문서 구조·ID·타임스탬프 형식에 맞춰 데이터 설계)

[화면별 요구사항]
1. 목록: 전체 건수(Total), 검색창, 글쓰기 버튼, 번호/제목/작성자/작성일/조회수 테이블,
   최신글 N 뱃지(최근 작성 글), 페이지네이션(페이지당 7건)
2. 상세: 목록으로 돌아가기, 제목/작성자/작성일/조회수, 공유·북마크 아이콘,
   본문(이미지 포함), 이전글/다음글 이동, 진입 시 조회수 +1
3. 글쓰기: 제목(필수), 카테고리, 내용(필수, 리치텍스트 에디터: 굵게/기울임/밑줄/목록/링크/이미지),
   첨부파일(최대 10MB / 10개), 취소·등록하기
4. 수정: 글쓰기 폼과 동일 + 노출 여부(공개/비공개), 기존 첨부파일 표시·삭제, 전체화면 토글, 취소·수정 완료

[공통]
- 헤더/푸터는 첨부 화면과 동일하게 유지, 기존 디자인 규약에 따른 디자인, 한글 UI
- 필수값 검증, 삭제 시 확인 창
- 첨부파일/이미지는 현재 Base64 등으로 localStorage 저장하되,
  용량 제한을 고려해 Firebase Storage 이관이 쉬운 구조(메타데이터와 파일 데이터 분리)로 설계

[산출물]
- 구현 코드 + 데이터 모델 정의 + 마이그레이션 시 교체할 지점 요약
