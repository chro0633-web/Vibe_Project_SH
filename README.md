## 0. 시작 절차 (순서 고정)

1. 이 `README.md`를 끝까지 읽는다.
2. `spec-kit/Agents.md`를 **전체** 읽는다. 특히 **PART S(프로젝트 전용)** 는 일반 규칙(PART A·B)보다 우선한다.
3. `task-history.md`를 읽어 이전 작업 결과와 남은 일을 확인한다. 이미 완료된 작업을 반복하지 않는다.
4. `spec-kit/reference/`의 원본 자료(HTML, CSS)를 열어 본다. 디자인 값의 근거다.
5. 현재 코드 상태를 확인한다. (`css/base/tokens.css`, `css/layout/`, 기존 컴포넌트)
6. **구현을 시작하기 전에** 아래 형식으로 **확인 보고**를 먼저 올린다. 오너가 승인하면 구현을 시작한다.

```
[확인 보고]
1. 이해한 내용 (5줄 이내): 무엇을, 어떤 구조로, 어떤 제약으로 만드는지
2. 이번 작업 범위: (예: tokens.css + 3단 박스 레이아웃 뼈대)
3. 가정한 사항: (있으면)
4. [추출 필요]/미확정 항목 중 이번 작업에 걸리는 것과 처리 방안
5. 오너에게 묻고 싶은 것 (최대 3개)
```

> 읽지 않은 문서를 읽은 것처럼 보고하지 않는다. 불확실하면 "읽지 못함"이라고 쓴다.

## 3. 절대 규칙 요약 (어기면 미완성)

상세와 예외는 `spec-kit/Agents.md`를 따른다. 아래는 기억용 요약이다.

1. **박스는 3단만**: `겉박스 > .inner-box > .part-box`. 그 외 래퍼 박스를 만들지 않는다.
2. **페이지 뼈대**는 `header` + `main > section` + `footer`. `main`의 직계 자식은 `section`뿐이다.
3. **`.inner-box`** 가 속박스의 유일한 이름이다. `.container`, `.wrapper`, `.inner` 등 동의어 금지. `max-inline-size` 기본 `1920px`, 중앙 정렬.
4. **파티션박스는 `flex`**, 줄바꿈이 필요하면 `flex-wrap: wrap`. **파티션박스에 `grid` 금지** (내용 박스 안에서만 허용).
5. **토큰이 단일 진실 공급원.** 색·간격·글자 크기를 컴포넌트에 직접 쓰지 않는다.
6. **`[추출 필요]` 값은 추측해서 채우지 않는다.** 오너에게 묻거나 측정 절차(PART S7)를 따른다.
7. **의존성을 추가하지 않는다.** (jQuery, GSAP, Swiper 등 모두 해당. 필요하면 먼저 승인을 받는다)
8. **접근성은 기능이다.** 키보드 조작, 포커스 표시, 대비 4.5:1, `prefers-reduced-motion`, JS 없이도 본문 표시.
9. **원본의 구현을 복제하지 않는다.** 디자인 값만 가져온다. (복제 금지 목록: PART S1.5)
10. **요청받은 범위만 수정한다.** 요청하지 않은 리팩터링·파일 이동·삭제를 하지 않는다.

## 4. 현재 상태와 미확정 사항

### 4.1 확정된 것
- 3단 박스 구조 및 클래스 이름 (`.site-header` / `.site-section` / `.site-footer` / `.inner-box` / `.part-box`)
- 본문 영역의 박스 수치, 글자 크기, 색상, 모션 값 (PART S3 · S4 · S5 · S6)
- 브레이크포인트 `813px` / `1400px`

### 4.2 아직 정해지지 않은 것 — **오너 확인 전에는 임의로 확정하지 않는다**

| # | 항목 | 현재 상태 | 처리 |
|---|---|---|---|
| 1 | 서체(`font-family`) | 원본 `common.css` 미제공 → **불명** | **`main.css`에서 개발** (4.3). 오너가 서체를 지정하기 전엔 시스템 폰트 스택 + `/* TODO(owner) */` |
| 2 | 헤더 · 푸터 · 검색 패널 · 전체 메뉴 수치 | **불명** (`common.css` 미제공) | **`main.css`에서 개발** → 제안·승인·기록 (4.3). 측정은 선택 |
| 3 | 브랜딩 섹션(`Shrouded Birth`) 포함 여부 | 원본에서 `display:none`(비노출) | 오너 확인 후 결정. 제외 시 마크업을 만들지 않는다 |
| 4 | 프로젝트 카드 목록 방식 | wrap(기본) vs 가로 스크롤 | 기본값 wrap으로 시작, 오너 선택 시 변경 |
| 5 | EN 본문 색 | 원본 `#5C5D64`는 대비 3.2:1로 미달 → 보정값 `#787981` 사용 중 | 오너가 원본 색을 요구하면 변경하고 미달 사실을 보고 |
| 6 | 애니메이션 라이브러리(GSAP) | 기본은 사용하지 않음 (`IntersectionObserver` + CSS) | 오너 승인 시에만 추가 |
| 7 | 커스텀 커서 | 원본에 존재, 스타일 불명 | 오너가 요구할 때만 구현 |
| 8 | 콘텐츠(작품 데이터, 소개 문구 최종본) | 원본 소개문에 오탈자 존재 | 원문 복사 금지. 오너에게 최종 텍스트 요청 |
| 9 | 페이지 범위 | HOME 외 Projects / Magazine / Exhibition / Index / Archive의 시안 없음 | 오너가 지시한 페이지만 만든다 |

### 4.3 `common.css` 처리 방침 (오너 결정)

`common.css`(서체 · 리셋 · 본문 기본값 · 헤더 · 푸터 · 검색 패널 · 전체 메뉴)는 **제공되지 않는다.** 대신 아래 방식으로 진행한다.

| 단계 | 내용 |
|---|---|
| 지금 | **`css/main.css`에서 개발**한다. 파일 길이 제한은 임시로 풀린다. `tokens.css`는 별도 파일로 둔다 |
| 개발 중 | `main.css`의 모든 코드는 **`[COMMON]` 존** 또는 **`[PAGE:이름]` 존**에 넣는다. 분류가 모호하면 `[PAGE]` |
| 값이 없는 항목 | 임의로 확정하지 않는다. **제안 → 오너 승인 → `docs/decisions.md` 기록** 순서. 승인 전엔 `/* TODO(owner) */` 임시값 |
| 나중에 | 오너가 요청하면 `[COMMON]` 존을 `css/common.css`로 **존 단위로 이전**한다. 시각 변화 0이 조건 |

- 에이전트는 **임의로 `common.css`를 만들지 않는다.**
- 규칙 상세: `spec-kit/Agents.md` **PART S9**

## 5. 작업 순서 (권장)

**한 번에 한 단계만** 한다. 각 단계 끝에 `spec-kit/Agents.md`의 완료 정의(DoD)와 PART S8을 확인하고 보고한다.

| 단계 | 작업 | 산출물 |
|---|---|---|
| 1 | 디자인 토큰 | `css/base/tokens.css` (색 · 글자 · 간격 · 모션 · z-index) |
| 2 | 리셋 · 베이스 | `reset.css`, `typography.css`, 포커스 스타일, `@layer` 순서 |
| 3 | 박스 3단 구조 | `css/layout/` — `.site-*`, `.inner-box`, `.part-box` |
| 4 | 공통 요소 | 헤더(GNB, 검색, 전체 메뉴), 푸터, 스킵 링크 — **`main.css`의 `[COMMON]` 존**에 작성, 미정 값은 제안 후 승인 |
| 5 | HOME 섹션 | 히어로 → 소개 → 전시 → (브랜딩) → 프로젝트 프리뷰 |
| 6 | 인터랙션 | 카드 호버/포커스, 버튼, 등장 연출, 영상 컨트롤 |
| 7 | 검증 | 접근성 · 성능 · 반응형 · 린트 |
| 8 | 서브 페이지 | 오너가 지시할 때만 |

## 6. 폴더 구조

```
/
├─ README.md                      ← 이 문서
├─ spec-kit/
│  ├─ Agents.md                   ← 규약 정본 (PART A·B·C·S)
│  └─ reference/                  ← 원본 HTML/CSS (읽기 전용)
├─ index.html
├─ pages/
├─ assets/ (fonts, images, icons, media)
├─ css/
│  ├─ base/tokens.css          ← 토큰 (분리 유지)
│  ├─ main.css                 ← 개발 단계 작업 파일 ([COMMON] + [PAGE:*] 존)
│  └─ common.css               ← (나중에 생성) [COMMON] 존 이전 결과
├─ js/ (main.js, modules, utils, config.js)
└─ docs/                          ← 컴포넌트 문서, 측정값(JSON), 결정 기록
```

폴더 상세 규칙은 `spec-kit/Agents.md`의 B2를 따르되, **CSS는 개발 단계에 한해 PART S9이 우선**한다. (`docs/decisions.md`에 오너 승인 결정값을 기록)

## 8. 보고 · 커밋 형식

**작업 완료 보고** (짧게)

1. 무엇을 만들었는지 (1~2문장)
2. 가정한 사항
3. 규약 예외와 그 이유 (있을 때만)

```
feat: 3단 박스 레이아웃 뼈대 추가
fix: 프로젝트 카드 키보드 포커스 시 정보 표시
```

## 9. 규약을 바꿔야 할 때

1. 코드를 먼저 고치지 않는다.
2. 변경 사유와 대안을 오너에게 보고한다.
3. 승인되면 **`spec-kit/Agents.md`를 먼저 수정**하고, 그 뒤에 코드를 수정한다.
4. 규약과 코드가 어긋난 것을 발견하면 임의로 맞추지 말고 보고한다.
